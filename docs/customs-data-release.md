## 3. 迁移

| 迁移 | 内容 |
| --- | --- |
| `20261109-012-customs-data` | 海关来源、公司、提单和匹配索引 |
| `20261109-013-customs-engagement` | 监控、提醒、评分和用量索引 |

部署顺序：

1. 备份 MongoDB。
2. 部署新代码。
3. 执行 `npm run migrate --prefix server`。
4. 启动 API 和 worker。
5. 用隔离项目导入样本数据，验证搜索、公司档案和客户动态。

## 4. 真实供应商接入清单

接入前必须完成：

- 供应商覆盖国家矩阵
- 字段字典和样本记录
- API、缓存、SaaS 嵌入和导出授权
- 数据延迟和更新频率确认
- 数据保留和删除条款
- 价格与年度记录量确认
- GDPR/隐私影响评估
- 失败重试和限流方案

接入时新增：

- 供应商 Adapter
- 凭证字段映射
- 同步游标
- 真实 HTTP/契约测试
- 数据质量抽样

## 5. 当前限制

- 尚未接真实海关数据供应商，当前测试使用隔离数据。
- 当前搜索读模型仍以 MongoDB 为主；数据量达到数百万票时再切换 OpenSearch 读模型。
- 尚未实现供应商 API 定时增量同步，当前以 CSV/JSON 导入为主。
- AI 建议依赖现有 AI Provider，未配置时自动回退规则建议。
- 欧洲覆盖需要按国家逐一验收，不做“全欧完整明细”的承诺。

## 6. 上线验收标准

- 搜索和公司 360 在目标样本上可用。
- 重复导入不产生重复提单记录。
- 客户可以匹配海关公司并查看贸易动态。
- 海关公司可以加入潜客池。
- 监控客户在新增提单后收到提醒。
- 评分包含可解释依据。
- AI 建议不编造记录，开发信必须人工审核。
- 搜索、导入和查看用量可查询。
- 跨项目无法读取海关数据。
- 真实数据不进入日志、测试快照和公开仓库。

## 7. 回滚

- 回滚应用版本不会删除已有海关数据。
- 如需停用，先将数据源状态设为 `disabled`，再停止导入。
- 迁移只新增索引，不删除已有业务数据。
- 真实供应商停用前先确认授权和数据保留义务。
